# 05 · AI 문서 추출기

세금계산서·견적서·영수증 PDF 를 읽어 **검증된 엑셀**로 만듭니다. LLM 은 DeepSeek API 를 사용합니다.

```bash
python make_sample_docs.py                       # 예시 문서 14건 + 정답지 생성 (이미 input/ 에 포함)
python ai_extract.py --provider rules            # 키 없이: 규칙 기반 기준선
python ai_extract.py --provider deepseek --dry-run   # API 호출 없이 대상·분량만 확인
python ai_extract.py --provider deepseek         # 실제 AI 추출
```

API 키는 프로젝트 루트의 `.env` 에 넣습니다 (`.gitignore` 로 업로드 제외됨).

```
DEEPSEEK_API_KEY=...
DEEPSEEK_MODEL=deepseek-chat        # 선택
```

## 설계

| 단계 | 내용 |
|---|---|
| 글자 추출 | `pypdf` 로 PDF 텍스트 레이어를 읽음 |
| 스캔본 판별 | 글자가 거의 없으면 **AI 를 호출하지 않고** `OCR 필요` 로 표시 (비용 절약 · 환각 방지) |
| 구조화 | LLM 이 JSON 으로 변환. 프롬프트로 "인쇄된 값만 옮기고 계산해서 채우지 말 것" 을 지시 |
| 정규화 | 날짜(`2026년 9월 3일`, `26-09-03` …) · 금액(`₩1,100,000`, `1,100,000원`) · 사업자번호 형식 통일 |
| 검증 | 사업자등록번호 검증 숫자 · 품목 합계 = 공급가액 · 세액 = 10% · 공급가액+세액 = 합계 |
| 재시도 | JSON 이 아닌 응답이면 최대 3회 다시 요청 |
| 출력 | `extracted.xlsx` (추출결과 · 품목 · 검토 필요 · 요약) · `extracted.json` · `run_summary.json` |

**왜 검증을 AI 가 아니라 코드로 하나요?**
AI 가 합계를 "알아서 맞춰" 적으면 원본 문서의 오타가 조용히 사라집니다.
이 프로젝트는 문서에 인쇄된 값을 그대로 옮기게 하고, 안 맞는 부분은 `검토 필요` 로 드러냅니다.

## 예시 문서 (전부 가상)

14건: 세금계산서 5 · 견적서 4 · 영수증 3 · 회의록 1(대상 아님) · 스캔본 1.
레이아웃·라벨·날짜/금액 표기가 제각각이고, 원본 자체의 오류를 일부러 넣었습니다.

| 문서 | 심어 둔 오류 | 기대 결과 |
|---|---|---|
| doc03 | 합계금액이 공급가액+세액과 1만 원 차이 | `TOTAL_SUM` |
| doc04 | 사업자등록번호 검증 숫자가 틀림 | `BIZNO_CHECKSUM` |
| doc05 | 공급가액이 품목 합계와 3만 원 차이 | `ITEMS_SUM` |
| doc14 | 이미지로만 된 스캔본 | `NEEDS_OCR` |

`ground_truth.json` 정답지와 비교해 필드별 정확도를 계산하고, 같은 문서로 **규칙 기반(정규식) 기준선**과 AI 를 비교합니다.
기준선은 "샘플 한 장을 보고 짠 정규식"을 가정한 것이라, 양식이 달라지면 깨집니다.

## 한계 (솔직하게)

- 현재는 **글자 레이어가 있는 PDF** 만 처리합니다. 스캔본·사진은 OCR 단계를 추가해야 합니다 (예: Tesseract).
- DeepSeek API 는 서버가 해외에 있습니다. **개인정보·거래 정보가 든 실제 문서는 고객 동의를 받거나 고객 본인 키로** 실행하세요.
- 정확도 숫자는 이 14건 기준입니다. 실제 고객 문서에서는 달라질 수 있어, 납품 전에 샘플로 먼저 확인합니다.
